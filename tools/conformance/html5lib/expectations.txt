#   - mathml-annotation-xml-integration-point (4 cases, tests20.dat): a `<math><annotation-xml
#     encoding="text/html"|"application/xhtml+xml">` (case-insensitively) is an HTML integration
#     point per the HTML Standard's tree-construction algorithm, so a subsequent HTML start tag
#     (e.g. `<div>`) must be inserted as its child, still processed with the ordinary "in body"
#     rules. html5ever 0.39 instead breaks the element out to a sibling of `<math>`, i.e. it
#     does not recognize `annotation-xml` as an HTML integration point for these two encoding
#     values. This is html5ever's own tree-builder foreign-content/integration-point logic
#     (crate `markup5ever`/`html5ever`, not `cl_html::sink` — the sink only receives html5ever's
#     `append`/`create_element` callbacks, it does not decide where they target), so it is not
#     fixable from within this crate's scope.
#   - selectedcontent-mirroring (2 cases, webkit02.dat): the HTML Standard's "Customizable
#     select" feature (added 2024/2025) specifies that a `<button><selectedcontent>` inside a
#     `<select>` mirrors the text content of the currently-selected `<option>` as part of tree
#     construction. html5ever 0.39 predates this addition and does not implement the mirroring
#     step — `<selectedcontent>` is built as an ordinary (empty) element, never populated. This
#     is a missing html5ever feature, not a bug reachable from `cl_html`/`cl_dom`.
