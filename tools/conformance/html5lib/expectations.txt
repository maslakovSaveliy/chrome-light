# Well above the M1a gate of 0.90. Three root-cause categories, all upstream of cl-html/cl-dom's
# own code (crates/html/src/** and crates/dom/src/** were not modified to produce this number —
# see this task's report for the full writeup):
#
#   - mathml-annotation-xml-integration-point (4 cases, tests20.dat): a `<math><annotation-xml
#     encoding="text/html"|"application/xhtml+xml">` (case-insensitively) is an HTML integration
#     point per the HTML Standard's tree-construction algorithm, so a subsequent HTML start tag
#     (e.g. `<div>`) must be inserted as its child, still processed with the ordinary "in body"
#     rules. html5ever 0.39 instead breaks the element out to a sibling of `<math>`, i.e. it
#     does not recognize `annotation-xml` as an HTML integration point for these two encoding
#     values. This is html5ever's own tree-builder foreign-content/integration-point logic
#     (crate `markup5ever`/`html5ever`, not `cl_html::sink` — the sink only receives html5ever's
#     `append`/`create_element` callbacks, it does not decide where they target), so it is not
#     fixable from within this crate's scope.
#   - attribute-sort-order-namespaced (1 case, webkit02.dat): `cl_dom::serialize::html5lib_tree`
#     sorts an element's attributes by `(namespace, local name)` (see its doc comment and
#     implementation), but the html5lib-tests corpus's own convention sorts by the *rendered*
#     attribute text (`"prefix local"` for an adjusted foreign attribute, the bare local name
#     otherwise) — confirmed by hand against this case: an SVG element with `xml:base`,
#     `xml:lang`, `xml:space`, `xml:baaah`, and `definitionurl` attributes. `xml:lang`/
#     `xml:space` are "adjusted foreign attributes" per the HTML Standard's attribute-adjustment
#     table (rendered `xml lang=""`/`xml space=""`, i.e. with a space, per
#     `cl_dom::serialize`'s own format for a namespaced attribute); `xml:base` and `xml:baaah`
#     are not in that table and stay literal (rendered with their colon intact). By
#     `(namespace, local)`, the un-namespaced attributes (`xml:base`, `xml:baaah`,
#     `definitionurl`, all in the empty namespace) sort before the XML-namespaced ones
#     (`xml lang`, `xml space`), because the empty namespace atom sorts before the XML
#     namespace URI. But the corpus expects `xml lang`/`xml space` first — because as *text*,
#     `"xml "` (space, 0x20) sorts before `"xml:"` (colon, 0x3A) in plain ASCII/byte order. This
#     is a real, narrow divergence in `crates/dom/src/serialize.rs`'s documented sort key
#     (out of this task's scope: `crates/dom/src/**` is explicitly off-limits here), triggered
#     only when a namespaced (adjusted foreign) attribute and a same-prefix-text un-namespaced
#     attribute are siblings on the same foreign element.
#   - selectedcontent-mirroring (2 cases, webkit02.dat): the HTML Standard's "Customizable
#     select" feature (added 2024/2025) specifies that a `<button><selectedcontent>` inside a
#     `<select>` mirrors the text content of the currently-selected `<option>` as part of tree
#     construction. html5ever 0.39 predates this addition and does not implement the mirroring
#     step — `<selectedcontent>` is built as an ordinary (empty) element, never populated. This
#     is a missing html5ever feature, not a bug reachable from `cl_html`/`cl_dom`.
#
