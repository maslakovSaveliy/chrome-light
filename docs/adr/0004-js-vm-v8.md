# ADR-0004: JS/Wasm VM — V8 behind the `JsRuntime` trait

**Status:** Accepted (revisit at M4)
**Date:** 2026-09-07
**Deciders:** project owner

## Context

The JS VM is a layer separate from the engine. Our own VM with an optimizing JIT is a multi-year program (the reference explicitly forbids including it in the MVP). The "behaves like Chrome" goal for JS is achievable only with V8: the same bugs, the same ECMAScript extensions, the same Wasm. The `v8` crate (rusty_v8) is stable since 129.0, versions = Chrome, prebuilt binaries, 152.2.0 as of 2026-09-07. Alternatives: `mozjs` 0.26 (SpiderMonkey, Servo), `boa` (pure Rust, slow, incomplete), our own.

## Decision

V8 via the `v8` crate, encapsulated in `cl-js` behind the `JsRuntime` trait (isolate/context creation, compilation/execution, promise/job queue hooks, inspector, snapshot, memory pressure API). No other crate imports `v8::` directly. One isolate per renderer main thread, a context per `Window`; workers — an isolate per thread. V8 update — within 7 days of a Chrome release (2-week cadence). JIT-less mode (`--jitless`) is a mandatory option (background tabs, "secure mode").

## Options Considered

| | V8 (`v8`) | SpiderMonkey (`mozjs`) | Boa | Our own |
|---|---|---|---|---|
| Chrome semantics | yes | almost | no | no |
| Idle isolate memory | ~2–5 MB + heap; reduced by snapshot/`--jitless` | comparable | small | — |
| Wasm | yes | yes | no | no |
| Inspector (CDP Debugger/Runtime) | built in → DevTools for free | exists, different protocol | no | no |
| Build | prebuilt, C++ in the binary (~30–40 MB) | complex, Python/Mach | cargo | — |
| Risk | C++ bugs, size | same + harder build | incompatibility, speed | years |

## Trade-off Analysis

V8 gives JS Chrome parity and the DevTools inspector at the cost of C++ in the TCB and binary size. The `JsRuntime` trait leaves a path to a Rust VM (Boa or our own) for specific modes (e.g., embedded/low-memory), but not for v1.

## Consequences

- Easier: JS compatibility, Wasm, Debugger/Profiler via V8 Inspector.
- Harder: V8 pulls in a C++ toolchain for building from source (we use prebuilt with checksum); we inherit V8's memory-safety bugs → the sandbox is critical; size.
- Revisit at M4: measure V8's share of memory in the budget; if >40% of the renderer on a typical page — investigate snapshot/lazy-isolate/Boa for background tabs.
